# RAG 切片可靠性修复设计

## 背景

当前论文审稿系统在 `paper_reviewer/rag/retriever.py` 中按章节、段落、句子和硬切分四个层级生成不超过 800 字符的文本块，再调用 Embedding API 构建进程内向量索引。

实测发现：

- `test2.pdf` 抽取出 48,969 字符，其中存在 17 个超过 800 字符的长句，最长 2,263 字符。当前递归切分无法保证每次递归都缩短输入，最终触发 `RecursionError`。
- `field_analyst_node()` 会捕获该异常并静默退化为全文，导致后台看起来像“切片没有生效”。
- 100 字符重叠只在硬切分路径生效，正常的章节、段落和句子切分之间没有重叠。
- 实际论文可能生成 54、56 字符的过短碎片，降低 Embedding 和召回质量。
- 3,000 字符以下的论文会有意跳过 RAG，但后台没有暴露这一状态。

## 目标

1. 任何输入都能在有限步骤内完成切分，不发生无限递归。
2. 所有文本块非空且不超过 800 字符。
3. 所有相邻文本块使用统一的约 100 字符上下文重叠。
4. 尽量保留章节编号和标题，并减少可安全合并的过短碎片。
5. 明确区分 RAG 成功、短文跳过、切片失败、Embedding 失败和查询失败。
6. 保持现有 `PaperIndex.retrieve(query, top_k)` 调用接口兼容。

## 非目标

本次不引入 BM25、reranker、FAISS、Chroma 或其他向量数据库，不更换 Embedding 模型，也不调整多审稿人图的业务职责。

## 方案选择

采用“稳健修复”方案：

- 保留现有分层语义切分思路。
- 增加递归进度判断和确定性的硬切分终止条件。
- 在基础语义片段生成后统一组装带重叠的最终文本块。
- 增加诊断信息和明确降级状态。

相比只修复递归，该方案同时解决上下文断裂和不可观测问题；相比完整替换检索架构，改动范围较小且不影响现有 Agent 接口。

## 切片设计

### 1. 章节识别

章节解析应保留完整标题文本，包括编号。标题作为所属内容的一部分进入文本块，避免当前 `re.split()` 丢失分隔符内容。

支持现有中英文标题形式，例如：

- `1 引言`
- `2.3 Research Design`
- `第一章 绪论`
- `Abstract`
- `Conclusion`

无法识别章节时直接进入段落切分，不阻塞后续流程。

### 2. 有限递归和硬切分

切分优先级保持为：

1. 章节
2. 空行分隔的段落
3. 句子边界
4. 滑动窗口硬切分

每次使用段落或句子切分后，先过滤空片段。只有得到至少两个有效片段，并且最长片段严格短于原输入时，才继续组合或递归。

如果切分没有产生进展，立即使用滑动窗口，窗口大小 800、步长 700，从而保证约 100 字符重叠并确定终止。

### 3. 统一块大小与重叠

语义片段先按约 700 字符的新内容容量组合，再为后续块携带前一块末尾最多 100 字符的上下文，使最终块长度不超过 800。

重叠只用于上下文连续性，不应造成正文丢失。测试会通过去除已知重叠后重建正文，验证内容覆盖。

### 4. 碎片处理

最终阶段尝试将过短块与相邻块合并。只有在以下条件同时满足时才合并：

- 合并后长度不超过 800；
- 不破坏章节顺序；
- 不造成重复重叠失控。

无法安全合并的短块允许保留，避免为了满足最小长度而丢失内容。

## RAG 状态与诊断

`PaperIndex` 提供只包含可序列化标量和列表的诊断信息：

- 原文字符数；
- chunk 数量；
- 最短、最长和平均 chunk 长度；
- 切片状态；
- Embedding 模型；
- Embedding 是否成功；
- 查询 Embedding 失败次数；
- 最近一次召回的请求 `top_k` 和实际数量。

运行策略区分：

- `skipped_short_document`：论文不超过 3,000 字符，按设计使用全文；
- `chunking_success`：切片完成；
- `embedding_success`：索引向量构建完成；
- `embedding_failed`：Embedding 失败，明确记录原因并降级；
- `query_embedding_failed`：查询向量失败，明确记录并使用确定性上下文降级。

异常信息只记录类型和安全摘要，不记录 API Key 或其他敏感配置。

## 数据流

```text
PDF/TXT 原文
  → 长度策略判断
  → 保留标题的语义切片
  → 有限递归或滑动窗口兜底
  → 统一重叠与碎片合并
  → chunk 统计
  → 批量 Embedding
  → 查询 Embedding
  → 余弦相似度 Top-K
  → 按原文顺序返回审稿上下文
```

短论文直接使用全文，但记录 `skipped_short_document`。任何降级都应保留可观察状态。

## 错误处理

- 切片函数自身不依赖外部服务，并保证对任意字符串终止。
- 索引 Embedding 失败时不让整条审稿流程中断，但必须记录失败原因。
- 查询 Embedding 失败时返回确定性的分散文本块，避免直接返回整篇长论文。
- 空 PDF 文本沿用上传层的错误处理范围，本次不扩展 OCR 功能。

## 测试设计

### 单元测试

- 空文本、短文本和单块文本。
- 1,700 字符无标点文本。
- 2,263 字符超长句子。
- 多章节中文和英文文本，验证标题编号保留。
- 多段落文本，验证统一重叠。
- 表格化或换行异常文本。
- 所有块非空且长度不超过 800。
- 切片可终止且内容覆盖无丢失。
- Embedding 使用桩函数时的 Top-K 和原文顺序。
- 索引及查询 Embedding 失败时的诊断与降级。

### 真实文件回归

- `test2.pdf`：不再触发 `RecursionError`。
- `test3.pdf`：稳定完成切分；所有块不超过 800 字符，并输出统计。
- 两个短 TXT 样本：明确判定为短文全文路径。

## 验收标准

- 全部现有测试通过。
- 新增切片测试通过。
- `test2.pdf` 和 `test3.pdf` 回归测试通过。
- 不调用真实 Embedding API 的单元测试可离线运行。
- 现有审稿 Agent 无需修改 `retrieve()` 调用方式。
- 后台日志或状态能够明确说明 RAG 是否实际生效及降级原因。
